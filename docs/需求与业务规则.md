# 学生选课与成绩管理系统｜需求与业务规则（第一版最终整合稿）

> **文档版本**：V1.0（阶段 0 需求讨论收口版）  
> **确认基准日**：2026-11-20  
> **适用范围**：项目第一版（单体应用），以学生、教师、管理员的真实教务业务闭环为目标。  
> **规则来源**：阶段 0 讨论形成的 CHG-001～CHG-072 及早期项目计划书。**冲突时以较新的、由用户明确确认的决定为准**。  
> **进度状态**：本文件是需求基线，不代表数据库、接口、测试或部署已经完成。  
> **归档建议**：保存为项目中的 `docs/需求与业务规则.md`。

## 0. 文档原则、范围与状态

### 0.1 文档用途

本文记录**最终应实现的业务行为、禁止行为、权限、数据约束及验收条件**。它不等于数据库设计说明、API 契约或代码实现计划。具体表结构、事务锁顺序、状态字段命名和异常返回码，在后续设计阶段确定，不能借“技术实现”改变本文已确认的业务规则。

凡是此前讨论中已经被后续决定覆盖的内容（例如先到先得选课、选退课共用截止时间、成绩发布后绝对不可更正、合法退课永不返还权重等），**不得再作为第一版有效规则实施**。

### 0.2 系统目标与主要角色

第一版提供从创建学期、课程和开课班级，到按权重选课和补选、上课与退课、成绩录入与发布、特殊考试、累计 GPA 和个人年级排名的完整闭环。

| 角色 | 业务职责 |
|---|---|
| 学生 | 查询可选课程、本人的报名/录取、课表、可用权重、正式成绩、累计 GPA 和本人同年级名次；在合法时段提交、撤回报名及退课 |
| 教师 | 查询本人授课班级与学生名单；按权限录入、审核期内调整成绩；发起已发布成绩更正申请；在被指定为特殊考试负责教师时处理相应批次成绩；查看本人授课班级统计 |
| 管理员 | 管理学生、教师账号与学籍、课程、学期、开课与排课、授课教师、成绩业务授权与特殊考试批次；查看全部合法统计范围并保留操作历史 |

### 0.3 第一版边界

- 第一版**不提供跨学期重修专用业务**；但底层历史修读模型不得通过“学生＋课程终身唯一”阻碍未来扩展。
- 第一版**不实现课程先修条件校验**；须保留课程身份与历史成绩以便未来扩展。
- 不做复杂自动排课、跨校区场地调度、支付、短信、完整培养方案、生产级统一身份认证。
- Redis、消息队列、微服务、Kubernetes、AI/Agent 等按后续实际需要扩展，**不算第一版必需业务**。
- 特殊考试的复杂异常补救、批次撤销重建等**未成为已确认的第一版需求**；不因本文未写细节而默认为支持。
- 第一版主要交付可用后端与可验证业务流程；完整商业级前端不是既定硬要求。学生“页面可见”可通过能展示信息的客户端或演示界面验证。

### 0.4 业务名词

| 名词 | 含义 |
|---|---|
| 课程（Course） | 目录中的一门课，例如《数据库原理》，具有课程编号、学分及选课范围 |
| 开课班级（Section） | 一门课程在某学期的具体授课安排；具有教师、课表、容量和开班状态 |
| 学期（Semester） | 从学校配置的某个星期一开始、连续 20 周的教学与考试周期 |
| 正常选课 | 第一轮正式选课，学生提交带权重的报名，轮末集中录取 |
| 两轮补选 | 正常选课结束后追加的两轮报名/权重竞争机会 |
| 报名 | 学生在选课阶段提交、即时扣除投入权重的申请；尚不保证超额竞争时录取 |
| 录取 / 有效选课 | 某轮结算后获得班级名额的关系；若班级尚不足最低人数，可处于待开班状态 |
| 当前正式成绩 | 学生目前已正式生效的课程结果；特殊考试或授权更正生效后以最新结果为准 |
| 特殊考试 | 本项目对普通补考、获批缺考和缓考后考试的统一管理批次 |
| 当前挂科 | 该课程目前正式认定的最终数值成绩不及格；历史曾不及格、后来补考通过不算当前挂科 |
| 同学年 / 同年级 | **同一入学年级**的学生，不是同一个教学班，也不是全校跨年级混排 |

## 1. 学籍、人员与账号

**STU-01｜学生基本数据**：每名学生具有唯一学号及基本信息，并明确所属专业、入学年级、学籍状态。对外查询须有相应身份或权限。

**STU-02｜学籍状态**：学生学籍包括 **正常在读、休学、退学、已毕业** 四类。

**STU-03｜选退课资格**：仅**正常在读**学生可以进行正常的选课、补选和退课业务；休学、退学及已毕业学生不能参与新选退课。

**STU-04｜历史可见性**：非正常在读学生仍可登录并查询本人的历史正式成绩；学籍变化不得删除已有成绩、选课及审计历史。

**STU-05｜恢复在读**：学籍恢复为正常在读后，重新按当前业务条件判断选课资格及累计 GPA 排名资格，不抹除停学期间的历史记录。

**ACC-01｜账号创建**：学生和教师及其账号由管理员创建；第一版不开放学生、教师自行公开注册获得有效身份。

**ACC-02｜身份归属**：学生只可操作本人报名、选退课、权重和查询结果；教师只可操作本人授课资源或被明确指定的特殊考试资源；管理员按职责访问管理信息。

**ACC-03｜历史数据**：教师、学生、课程被停用或状态变化时，有关联的开课、成绩和审计信息不能因为该变更被破坏。

## 2. 学期、周次与时间规则

**SEM-01｜学期长度**：一个学期连续 **20 周**；第 **1～18 周**为教学周，第 **19～20 周**为考试周。第 20 周仍属于进行中的学期。

**SEM-02｜起始日**：学期由管理员配置第 1 周的星期一作为起点。各周按自然周连续递增；第 20 周星期日为学期最后一天；允许跨自然年度。

**SEM-03｜状态自动判定**：依据学校采用的统一时区和当前日期自动计算 `PLANNED / IN_PROGRESS / FINISHED`：开始前为待开始；第 1 周星期一起至第 20 周星期日止为进行中；之后为已结束。不得随意手动切换以绕过时间限制。

**SEM-04｜起始日冻结**：学期起始星期一只能在**从未创建过任何开课班级**之前修改。已有创建历史后不得通过删除班级重新放开修改。

**SEM-05｜独立业务窗口**：学期状态、选课窗口、退课窗口、正常成绩截止时间以及成绩审核期分别判定，不能把“学期进行中”直接等同于“任何业务都可以操作”。

**SEM-06｜时间处理**：所有时间界限使用同一所学校统一配置的时区；需要明确起止时刻及边界包含关系。具体时间字段类型与调度手段在设计阶段确定。

## 3. 课程、开课班级与排课

### 3.1 课程目录与限制

**CRS-01｜课程基础信息**：课程具有唯一编号、名称、学分以及可选学生范围。

**CRS-02｜学分冻结**：一旦课程曾用于创建开课班级，其学分不再允许通过普通编辑功能修改；历史 GPA 不因目录被随意编辑而重算。

**CRS-03｜专业和年级限制**：每门课程可按需要限制允许选课的专业和入学年级；也可对专业或年级**不设限制**，允许符合其他条件的学生报名。存在限制时必须满足相应条件。服务端不得只靠隐藏界面选项执行限制。

**CRS-04｜课程停用而非历史删除**：管理员可以将课程设置为以后不再开设；停用后不得为后续教学创建新的开课班级，但**已创建且正在进行的班级照常教学**，历史课程、成绩、学分与 GPA 继续有效。

**CRS-05｜后续扩展**：预留可建立课程先修关系的可能性，第一版不实施该校验，也不提前实现复杂先修体系。

### 3.2 开课班级、容量与人数门槛

**SEC-01｜开课信息**：某门课程在某学期可创建一个或多个开课班级；关联授课教师、课表及容量。

**SEC-02｜最大容量**：每个班级的最大容量必须是**大于 0 的偶数**。学生有效录取人数不得超过最大容量。

**SEC-03｜最低人数**：最低开班人数固定为 `最大容量 ÷ 2`。例如上限 40，最低 20。因上限必须为偶数，不存在取整问题。

**SEC-04｜容量调整**：开课后可以在权限与状态允许时调整容量，但新容量仍必须为**正偶数**，且不得小于当前有效录取人数；调整不得制造超额名额。

**SEC-05｜课表冻结**：开课班级在草稿阶段可以编辑教学时间；进入对学生开放的状态后，教学周、星期、节次等课表信息冻结，不提供普通调课绕过冲突检查。

**SEC-06｜教师调整**：管理员可以更换授课教师，但必须对新教师重新校验课表冲突并记录原教师、新教师、操作人、时间和原因。更换教师不能清除原学生选课关系。

### 3.3 教学时间与冲突

**SCH-01｜教学周**：每个开课班级可拥有多个上课时间片段，每个片段具有**指定教学周集合、星期和节次区间**。教学周可以是不连续集合，例如 `{1,3,5,7}`，不能强制视为整个学期每周均上课。

**SCH-02｜节次区间**：相同星期的节次区间按半开区间比较；只有**教学周有交集、星期相同、节次有交集**三者同时成立才认定时间冲突。边界相接不算节次重叠。

**SCH-03｜教师冲突**：同一教师不得同时承担时间实际重叠的不同独立开课班级。

**SCH-04｜合班边界**：单个开课班级可以招收不同专业/行政班的学生；第一版**不实现多个独立 Section ID 共用同一合班教学活动**来规避教师课表冲突。

**SCH-05｜学生冲突**：学生在同一学期的既有有效选课及尚未撤销、尚未结算的有效报名均参加冲突检查。**提交报名时立即拒绝时间冲突**；不允许先同时竞选冲突课程、结算时再自动二选一。

**SCH-06｜同课多班**：同一学生在**同一学期同一门课程**最多只能有一个有效选课或有效报名目标；不能同时报名同课程的不同开课班级。跨学期历史记录须允许保存，但重修的专用业务第一版不提供。

## 4. 正常选课、权重竞争与两轮补选

### 4.1 时间和资格

**ENR-01｜正常选课窗口**：每学期在**学期开始日期前 14 天**开启正常选课，持续 **3 个自然日**。此决定取代此前的 7 天以及原先约两周的持续时间。

**ENR-02｜补选窗口**：正常选课结束后依次设置**第一次补选 2 天**、**第二次补选 1 天**。两轮结束后不再安排第三轮常规补选。具体开始/结束时刻由统一的学期窗口确定，不按每个班级任意另定。

**ENR-03｜资格检查**：报名时必须同时通过正常在读、课程专业和入学年级范围、开课班级状态、同学期同课程唯一、学生课表冲突等校验；不能凭重复或并发请求绕过。

**ENR-04｜可见权重余额**：学生可以查看本学期**当前可用选课权重余额**。

### 4.2 权重来源、投入和余额

**WGT-01｜初始额度**：本学期正常选课开始时，符合选课资格的学生获得 **100 点**初始权重。

**WGT-02｜第一次补选增加**：第一次补选开始时，**所有符合当期选课资格的学生**统一额外增加 **50 点**权重，不只给落选学生。每个学生每学期不得重复领取。

**WGT-03｜提交即扣**：学生选择投入一定权重提交报名申请，提交成功时立即从**可用余额**扣除该笔权重。不得超出当前可用额度；被业务校验拒绝的申请不得扣权重。

**WGT-04｜独立申请记账**：应能区分学生不同报名分别投入的权重；同时提交多门不冲突的课程时，各笔投入合计受当前可用余额约束，不能重复使用同一笔余额。

**WGT-05｜报名不等于最终录取**：成功报名后等待本轮结束结算；尤其超额报名时，不得因先提交就永久锁定名额。

**WGT-06｜本轮撤回**：本轮截止前，学生可撤回尚未最终结算的报名，释放该申请已经扣除的权重。重复撤回不得重复返还。

### 4.3 每轮录取与开班判定

**SEL-01｜按剩余容量结算**：每轮结束后，在班级尚有可录取名额时结算该轮有效报名；**此前轮次已经确定的名额不会被下一轮更高权重者挤掉**。

**SEL-02｜未超过剩余容量**：有效报名人数不超过本轮剩余容量，且申请资格合法时，这些学生都获得相应名额；但若班级尚未达到最低开班人数，应标为**待开班**，不能冒充已经保证开班。

**SEL-03｜超过剩余容量**：根据每名报名者对该班级投入权重从高到低录取，最多录取至剩余容量。**投入权重相同且竞争剩余名额时随机决定**。系统应固定已经结算的随机结果，重复结算不得重新抽签。

**SEL-04｜竞争落选返还**：未获得名额的学生返还该申请投入的权重；成功获得名额的学生其投入继续处于已扣除状态。

**SEL-05｜开班门槛**：判断班级是否达到最低开班人数时，以有效录取人数而不是全部未结算报名人数为准。达到门槛就确认可以开班；未达到则保持待开班，在后续补选接受符合条件的报名。

**SEL-06｜确认开班后稳定**：班级一经确认可以开班，后续合法退课即使令人数跌破最低门槛，也**不自动取消**已确认的开班。

**SEL-07｜最终不足人数**：第二次补选完成结算后，仍未达到最低人数的待开班班级取消。其原有名额关系被撤销，已扣权重按相关规则返还，并保留取消及变更历史。

**SEL-08｜无保底**：所有选课轮次完成后仍未成功获得可开班课程名额的学生，不额外安排第三轮选课，也不保证一定选上。

**SEL-09｜前述规则的优先顺序**：资格与冲突先校验；报名立即扣权重；每轮截止后按剩余容量和权重确定名额；再按实际录取人数判断开班；最终轮处理未开班取消；最后清零本学期可用权重。

### 4.4 退课和权重返还

**DROP-01｜时间窗口**：普通退课遵守统一规则——**从对应开课班级首次实际上课日起 7 天内**允许办理；班级之间可以有不同的首次上课日期。具体截止时刻以统一学校时区计算。

**DROP-02｜成绩锁定**：该开课班级只要已有任何有效学生的成绩开始录入，**整个班级的普通退课都锁定**，不能只禁止已录成绩的个别学生退课。

**DROP-03｜合法退课效果**：成功退课后删除当前有效选课关系（保留单独审计记录），释放班级名额；退课操作必须防止重复释放容量或重复返还权重。

**DROP-04｜权重有效期内**：在选课与补选尚未完成全部最终结算、权重仍有效的阶段，合法退课返还该次选课已扣的权重。未结算报名的主动退出按报名撤回处理。

**DROP-05｜第二轮结束后**：第二轮补选截止后，先完成录取、落选返还、未开班取消及相关返还，**再将剩余可用权重清零并使其失效**。

**DROP-06｜清零后的退课**：清零之后，即使学生仍满足合法退课条件，也**只退课并释放容量，不恢复任何可用权重余额**。原始投入及业务历史仍保留。余额清零不能阻碍合法退课。

**DROP-07｜报名失败与取消**：业务拒绝不扣；截止前撤回、权重竞争落选或班级最终取消时，按结算先后返还已扣额度，不得发生重复加回。完成最终清零后，不得通过补退课恢复可用于当期选课的额度。

**DROP-08｜不可越权**：学籍非正常、退课时间届满、成绩已开始录入或缺少有效选课关系时，拒绝普通退课。

### 4.5 第一版选课流程实例（仅示意）

假设某学期开始日为 3 月 1 日：正常选课从距该日 14 天的日期开始，共 3 天；之后第一轮补选 2 天，第二轮补选 1 天。学生起始可用权重为 100 点，提交 Java 选课并投入 40 点，余额立即变为 60 点；提交 Python 并投入 30 点，余额变为 30 点。若 Python 落选，则返还 30 点；若 Java 班级最终不开，也返还该笔 40 点。第一轮补选开始统一额外发放 50 点。第二轮全部结算后余额归零，随后发生的合法退课不再恢复可用权重。

此示意不代替正式窗口时间计算；**正常选课开始日**已确认，但各阶段是否紧密连续、每日起止小时等细节由后续业务配置和设计确定。

## 5. 正常成绩管理、审核与发布

### 5.1 成绩结果类型与有效性

**GRD-01｜成绩分类**：正常课程结果区分：**数值成绩（0～100）、缺考、缓考、未录入**。其中 **0 是正式数值成绩，不等于未录入**。

**GRD-02｜缺考批准状态**：缺考须保留是否获批的业务事实；未经批准的原始缺考在原成绩正式发布后按**不及格、原成绩 0**认定，适用普通补考资格和封顶规则；获批缺考按照特殊考试规则处理。

**GRD-03｜完成录入的判断**：已明确记录的缺考、缓考可以计为本轮成绩录入“已完成”的状态；**未录入**不算完成。已记录缺考或缓考不能因为暂时没有数值成绩，就阻止整个班级进入审核流程。

**GRD-04｜公开条件**：正常班级成绩按**开课班级整体**发布，审核期未结束前学生不能看到未正式生效的本轮结果。

### 5.2 首次录齐、审核、自动发布

**GRD-05｜首次录齐触发**：一旦某班级所有有效选课学生首次都有合法、已记录的成绩或特殊状态，系统自动开始**72 小时（3×24 小时）审核期**。

**GRD-06｜审核期调整**：授课教师可在审核期内修正自己班级的已录结果；不能通过把已录成绩清空成“未录入”来解除完整性条件，也不能靠修改重启审核倒计时。

**GRD-07｜自动整体发布**：审核期届满后自动把该班级成绩整体发布，保证相关结果同时正式生效。无需教师手工逐人发布，也不能因为某个学生有批准的缓考而无限等待特殊考试。

**GRD-08｜学生可见性**：审核期间只允许学生看到此前**已经正式生效**的结果（如存在）；本次未正式发布的成绩、补考结果和更正结果不得提前公开。

**GRD-09｜防重复及并发**：多次触发审核、定时任务重复执行、录入与发布并发都不能导致审核期重启、重复发布或一部分学生正式一部分仍未正式的错误状态。

### 5.3 学期成绩录入截止时间

**DEAD-01｜统一截止**：每个学期有一个普通成绩录入截止时间，与 72 小时审核期、成绩正式生效时间**相互独立**。

**DEAD-02｜默认值**：默认截止为第 20 周星期日结束后的**第 14 天**；允许管理员按学期配置。

**DEAD-03｜合法区间**：截止日最早不得早于**第 20 周星期日**，最晚不得超过其后 **30 天**；截止日以学校统一时区的**当日整天包含**方式处理。

**DEAD-04｜变更权限**：管理员只有在**现有截止时间尚未过期**时才能修改学期普通录入截止时间，须保存操作原因和变更记录。过期后不能靠延长普通截止来补录。

**DEAD-05｜截止效果**：超过普通截止后，教师不能继续通过普通入口补齐尚未录入的课程成绩；已在进行的合法 72 小时审核及其到期自动发布不因此被取消。

**DEAD-06｜针对班级的补录授权**：管理员可以对指定开课班级给予临时**迟交成绩录入许可**，明确开始、结束、原因；不同授权可分段存在，但不得在时间上重叠，并需保留授权历史。

**DEAD-07｜补录授权边界**：迟交授权只允许符合条件的尚未最终录入情况得到处理；不能绕过已经发布成绩的更正规则，不能重新启动正常审核期，也不能替代正式成绩更正审批。

## 6. 已发布成绩更正

**COR-01｜更正申请**：正常成绩正式发布以后，教师不能通过普通录入功能直接修改，应提出对应成绩更正申请，由管理员审核。

**COR-02｜精准授权**：管理员批准时应明确允许更正的**指定学生、目标数值成绩、有效截止时间**等范围；授权不等于允许随意批量改分。

**COR-03｜教师执行**：获批后由符合授权的教师在有效期内实际提交更正；只有**教师成功执行写入**时新成绩才正式生效，**不再进行另一轮 72 小时审核**。

**COR-04｜学生看到什么**：申请待审或已批准但未执行时，学生依然只看到旧的正式成绩；执行成功后才看到新结果。学生不查看教师内部的更正申请流程状态。

**COR-05｜同一成绩唯一活动流程**：同一学生同一开课班级，同一时刻至多存在一条仍在等待审核或已获批尚未执行的活动更正申请。被驳回、撤回、失效或完成后，可重新申请，历史不清除。

**COR-06｜教师撤回**：教师可以撤回自己尚在**待审核**的更正申请；撤回后不得再批准该申请。

**COR-07｜到期失效**：批准授权到期但未完成执行时，自动失效并结束该活动申请；不能以已失效授权改成绩，也不能永久占据该成绩的申请名额。

**COR-08｜审计与重算**：保存更正原因、申请审批、原成绩、新成绩、执行者和时间等必要历史；更正正式生效后，受影响的课程统计、累计 GPA 和年级排名以新正式成绩计算。

**COR-09｜与迟交录入区分**：已发布成绩更正与尚未录完的迟交成绩补录是两种不同业务，不得混用授权。

## 7. 缺考、缓考、补考与特殊考试批次

### 7.1 资格与最终成绩认定

**EXM-01｜统一批次业务**：普通补考、批准缓考和批准缺考后的考试，采用同一门课在同一学期的**特殊考试批次**进行管理，不为每个原开课班级分别造重复的补考批次。

**EXM-02｜普通不及格资格**：原课程正式成绩不足 60 分的学生自动取得该课程普通补考资格；此资格需以**正式发布**的原课程结果为依据。

**EXM-03｜未经批准缺考**：原考试缺考但未获得批准，原课程按**正式数值成绩 0**作为不及格处理，自动获得普通补考资格；不适用获批缺考的高分照实认定。

**EXM-04｜获批缺考或缓考**：有合法批准的缺考或缓考学生符合特殊考试资格；在取得正式数值成绩前，该课程尚无可用于 GPA 的数值分数。

**EXM-05｜及格线**：全体课程统一以 **60 分**为及格标准。

**EXM-06｜普通补考通过**：普通不及格（包括未经批准缺考视为原成绩 0）的学生，特殊考试原始分数达到 60，最终课程成绩**统一认定为 60 分**，单科绩点 **1.0**；即使补考原始分为 85、90，也不能按高分给绩点。

**EXM-07｜获批特殊考试通过**：获批缺考或缓考学生，特殊考试原始成绩达到 60，最终课程成绩使用**实际原始成绩**（例如考 90 则最终 90，绩点按 90 计算）。

**EXM-08｜特殊考试不及格**：所有适用特殊考试的学生，特殊考试原始分数低于 60，最终课程成绩认定为 **0 分**、绩点 **0**。

**EXM-09｜特殊考试再缺考**：参加特殊考试却再次缺考，记录缺考事实，并把该次考试结果按**数值 0**处理；该结果属于已经录入的批次结果，等待批次审核与正式生效。

**EXM-10｜当前挂科消除**：原来挂科但普通补考通过并正式生效后，该课程不再算**当前挂科**。历史不及格和补考原始分仍留存供授权审计，但同 GPA 排名不以历史挂科继续扣名次。

**EXM-11｜分数层次**：需要区分原考试记录、特殊考试原始分、最终认定课程分数、资格类型和相应生效时间；不得用最终 60 覆盖唯一可追溯的真实考试原始成绩。

### 7.2 批次建立与学生名单

**BAT-01｜唯一批次**：同一**学期 × 课程**最多存在一个特殊考试批次。不同原开课班级的同课程学生共同归入该批次，最终结果回写至各自原选课关系。

**BAT-02｜系统自动汇总**：系统根据正式成绩和合法批准状态，**自动汇总所有符合资格的学生**；在名单冻结之前，新取得资格者应及时纳入，而不是要求管理员逐个手工添加普通资格学生。

**BAT-03｜考试前冻结**：管理员在考试前**确认并冻结参加学生名单**，此后不再进行正常添加/删除。名单未确认冻结不得进入特殊考试成绩录入。

**BAT-04｜批次负责人**：管理员指定一名或多名负责教师；他们可在授权范围内录入、修改该特殊考试批次的成绩，**不因此获得其他普通开课班级改分权限**。

**BAT-05｜负责人变更**：在批次结果正式生效前，管理员可有理由、可审计地增加、移除或替换负责教师；在审核期内允许这类变动，但不能重置审核期或修改已冻结学生名单。

**BAT-06｜简单化边界**：第一版不要求建设考场/监考排班，不设相同课程的第二个补救批次，也不预先设计复杂的已冻结名单例外补入、整批撤销重建流程；未明确的异常情况不擅自承诺支持。

### 7.3 批次录入、审核、生效

**BAT-07｜全部录齐后审核**：批次冻结名单中所有学生都有合法已录考试结果（包含特殊考试再次缺考记 0）后，自动进入**72 小时审核期**。

**BAT-08｜到期统一生效**：72 小时届满后，批次结果整体正式生效，并按照每个人的资格类型分别计算最终课程成绩；不能让同一批次部分学生提前生效。

**BAT-09｜原班级不再审核一次**：特殊考试的正式结果回写原开课班级对应学生的最终成绩时，不重新触发原班级的首轮 72 小时审核。

**BAT-10｜原成绩过渡**：特殊考试批次审核期间，学生查看的仍是其此前已经正式生效的课程成绩或状态；批次正式生效后才看到最新最终认定结果。

**BAT-11｜并发及历史**：批次自动生效必须可重复执行而不重复改分；保留原成绩、原始特殊考试成绩、最终认定成绩及关键操作历史。

## 8. GPA、挂科和同入学年级排名

### 8.1 GPA 计算

**GPA-01｜统计时间范围**：采用**历学期累计 GPA**，不采用单学期 GPA 作为本项目的学生排名依据。

**GPA-02｜单科绩点**：正式有效的课程最终认定数值成绩 **≥60** 时，`单科绩点 = (最终认定成绩 - 50) / 10`，例如：60→1.0；70→2.0；80→3.0；90→4.0；100→5.0。

**GPA-03｜不及格绩点**：最终有效数值成绩不足 60 的课程，单科绩点 **0**；**课程学分仍参与累计 GPA 分母**，不能因不及格就把学分从 GPA 中剔除。

**GPA-04｜累计公式**：

`累计 GPA = Σ(参与统计的课程学分 × 课程绩点) / Σ(参与统计的课程学分)`。

**GPA-05｜特殊状态暂不计入**：获批缓考或获批缺考等**尚无正式生效数值成绩**的课程，暂不计入分子和分母。取得正式数值成绩后再参与；未经批准缺考按正式 0 分的规则处理。

**GPA-06｜以最终正式成绩为准**：普通补考通过计 60 分及绩点 1.0；获批缺考/缓考按适用的最终认定成绩；已执行的合法更正使用最新正式数值成绩；不拿尚在 72 小时审核中的原始分重算。

**GPA-07｜没有数据**：没有任何可计入 GPA 的正式数值成绩课程时，累计 GPA 为“暂无数据”，**不是 0**。

**GPA-08｜计算精度**：使用足够精度的原始累计结果进行比较与排名，不按页面显示的四舍五入结果决定两人是否同 GPA；具体存储精度在设计阶段统一。

### 8.2 排名条件与排序

**RANK-01｜排名范围**：按**相同入学年级**分别排名。不同入学年级的学生不在同一榜单比较。

**RANK-02｜参与资格**：只有**正常在读**且**至少具有一门正式有效数值成绩课程**的学生参与当前排名。**不设置最低累计学分门槛**。

**RANK-03｜学籍排除**：休学、退学、已毕业等学生不参与当前排名；恢复正常在读时符合成绩条件则重新参与。历史成绩与 GPA 不删除。

**RANK-04｜第一排序项**：按累计 GPA **从高到低**排列。

**RANK-05｜同 GPA 次级项**：GPA 完全相同，则**没有当前挂科课程者优先**于仍有当前挂科课程者；不按历史是否曾挂科继续惩罚补考通过者。

**RANK-06｜并列**：累计 GPA 相同且当前挂科“有/无”条件相同者并列；不再按挂科门数、学分、姓名等增加额外名次排序条件。

**RANK-07｜名次编号**：采用竞赛排名 **`RANK()`** 的跳号方式，例如 **1、1、3、4**，不是 `DENSE_RANK()` 的 1、1、2、3。

**RANK-08｜学生个人查询**：学生只能看到自己在同一入学年级中的名次；**不提供完整年级排行榜或查询其他学生姓名、绩点和名次的接口**。

**RANK-09｜动态重算**：学籍状态变化、新学期正式成绩生效、特殊考试统一生效、已发布成绩获批且执行更正时，相关同年级名次按最新正式状态更新。

### 8.3 例子与预期

| 学生（均为同一入学年级） | 累计 GPA | 当前挂科 | 排名 |
|---|---:|---|---:|
| 张三 | 4.20 | 无 | 1 |
| 李四 | 4.20 | 无 | 1 |
| 王五 | 4.20 | 有 | 3 |
| 赵六 | 4.00 | 无 | 4 |
| 孙七 | 4.00 | 无 | 4 |
| 周八 | 3.80 | 无 | 6 |

曾挂科但补考通过（最终认定 60 分、绩点 1.0）的课程，不算“当前挂科”。如果两人的累计 GPA 相同且当前都没有挂科，则并列。

## 9. 成绩查询、统计与数据可见性

**VIEW-01｜学生成绩**：学生只看到本人当前**正式有效**的课程最终数值成绩；若正式结果仍是缺考/缓考等无数值特殊状态，则显示相应已发布状态。学生普通查询不暴露原考试原始分、补考原始分、后台更正审批记录及其他学生成绩。

**VIEW-02｜当前有效性**：特殊考试审核期间保持原正式结果可见；批次正式生效才展示新最终成绩；更正申请批准但未执行时仍展示旧成绩。

**STAT-01｜开课班级平均分**：只纳入该班级**已经正式生效且具有数值的当前最终认定成绩**；正式不及格的 0 分应参与平均；缓考、批准缺考等无数值状态暂不参与。

**STAT-02｜没有成绩数据**：一个班级尚无可参与统计的正式数值成绩时，平均分应显示“暂无数据”，而非错误地显示 0 分。

**STAT-03｜正式成绩变更**：特殊考试批次生效、已发布成绩合法更正后，课程统计以新的正式最终认定结果更新。

**STAT-04｜教师权限**：普通授课教师只可查看**本人负责的开课班级**成绩统计；担任特殊考试负责教师不自动授予其他普通班级统计权限。

**STAT-05｜管理员权限**：管理员可查看全部符合职责的成绩统计；学生不能借统计接口获取其他学生个体数据或完整年级榜单。

## 10. 关键业务状态、审计与一致性要求

### 10.1 必须明确的业务状态区别

| 领域 | 必须区分的含义 |
|---|---|
| 学期 | 待开始、进行中、已结束；由日期自动决定 |
| 课程 | 当前有效 / 已停用；停用不删除历史或正在进行的班级 |
| 开课班级 | 草稿、可报名/办理选课、待开班、已确认开班、最终不开等必要业务含义；具体字段/状态机待设计 |
| 学生选课 | 本轮报名、已撤回、录取成功、竞争落选、待开班名额、合法退课、因班级取消解除 |
| 权重 | 可用余额、某报名已扣权重、发放、释放、落选返还、退课返还、最终清零 |
| 普通成绩 | 未录入、已记录、72 小时审核中、正式已发布 |
| 已发布更正 | 待审核、拒绝、批准未执行、已执行、主动撤回、到期失效 |
| 特殊考试 | 资格自动汇总、名单冻结、成绩录入、72 小时审核、批次正式生效 |

**说明**：上表描述业务必须可区分的事实，**不是**已确认要创建的具体数据库枚举值或固定状态字段集合。

### 10.2 不可违反的业务不变量

1. 开课班级最大容量为正偶数；`0 ≤ 有效录取人数 ≤ 最大容量`。
2. 最低开班人数始终为该班级当前合法最大容量的二分之一；已确认开班后不会因正常退课自动取消。
3. 同一学生同学期同课程同时至多存在一个有效报名/选课目标；同一学生不得拥有实际时间冲突的有效报名或选课。
4. 学生可用选课权重不得为负；每次合法业务变化都不得重复扣除、返还或发放权重。
5. 轮次录取结果不可因重复结算改变；同权重随机不能因重复任务重新抽取。
6. 本轮实际录取不超过剩余容量；已录取者不被以后轮次投更高权重的学生替换。
7. 班级最终不开需撤销相关选课名额并处理已扣权重；所有必要历史应可追溯。
8. 学生不得看到尚未正式生效的成绩；72 小时审核期不得因重复修改而重新计时。
9. 特殊考试同一学期同课程至多一个批次；正式批次成绩整体生效。
10. GPA 只基于正式有效的最终成绩；课程挂科、缓考、获批缺考、补考后的绩点边界正确。
11. 只有具备资格的正常在读学生参与本入学年级竞赛排名；学生只能看到本人名次。
12. 所有业务写操作须进行身份和资源权限校验；并发下的结果应与单一合法操作顺序一致。

### 10.3 必须保存的历史与审计信息

- 学生学籍状态变更历史及其对当前资格的影响。
- 课程停用、开课班级变化、授课教师更换和必要原因。
- 报名、每笔投入权重、结算录取/落选、随机录取结果、权重发放/扣除/返还/清零、退课与班级取消事件。
- 正常成绩审核触发和正式发布时间、合法迟交授权与截止时间变更。
- 已发布成绩更正的申请、审批、撤回、到期失效、执行前后分数。
- 特殊考试资格来源、冻结名单、负责教师及变更、原考试与特殊考试原始结果、最终认定结果、正式生效时间。

## 12. 历史变更覆盖关系（整理时不可遗漏）

本表总结**最终规则应如何覆盖早期规则**，不替代每个 CHG 的原始讨论文本。

| 早期或曾提议的规则 | 最终有效规则 | 主要关联变更 |
|---|---|---|
| 先请求者占到最后一个名额 | 按轮次报名并即时扣权重；轮末按权重结算，同权重随机 | CHG-059、065、069、070 |
| 普通选课持续 7 天或开学前约 14 天全部开放 | 学期开始前 14 天**开启**，正常选课持续 **3 天**；补选 2 天、1 天 | CHG-057、060、064 |
| 普通退课与选课窗口相同 | 退课按开课班级首次实际开课日起 7 天内，且受成绩开始录入限制 | CHG-054、057、071 |
| 正式录取后退课不返还权重 | 权重未失效前合法退课可返还；第二轮全部结算及清零后不恢复可用权重 | CHG-069、070、071 |
| 人数不达标立即永久取消 | 待开班可等待后续补选；最终轮仍不足则取消；已确认开班不因合法退课自动撤销 | CHG-056、066、069、072 |

| 成绩录齐后教师手动发布 | 首次录齐触发 72 小时审核，到期自动整体发布 | CHG-003、015、023、027 |

| 缺考一律必须审批才能补考 | 未批准缺考按原 0 分的不及格自动取得普通补考资格；获批缺考按批准类型处理 | CHG-024、036、037 |

## 13. 明确不新增的第一版业务与留给设计阶段的细节

### 13.1 不再作为需求阶段的额外选择题

- 不增加复杂的特殊考试批次撤销重建、冻结后反复补入和多轮补救考试机制。
- 不增加复杂的成绩申诉多级流转；沿用已确认的管理员批准教师更正。
- 不将先修课程、跨学期重修、教学活动合班多 Section、自动排课引擎当成第一版已确认的功能。
- 不为学籍状态、上课人数不足或选课竞争失败引入未确认的复杂保底/申诉流程。

### 13.2 后续设计必须说明，但当前**不得假定已由用户确认**

1. **权重数值输入的合法最小单位和范围**：允许投入哪些正数、是否只接受整数；需与余额规则、表字段和输入校验一致。
2. **阶段时刻配置**：正常选课开始日前已确认，但 3 天、2 天、1 天三个窗口的具体开始/结束小时及是否无缝衔接尚未被明确到时刻，需统一定义，不得擅自写成已经确认。
3. **待开班名额的中途退出与改选**：班级尚未达到最低人数、学生已获暂定名额时，若希望在后续补选转投其他班级，具体是“撤销待开班名额”还是“普通退课”以及资格时间边界，需要在设计评审中统一，避免学生因尚未开班又不能改选而被锁住权重。
4. **确认开班与容量修改交错**：若管理员在待开班阶段修改容量，最低人数随新容量变化；必须定义与轮末结算的先后和并发校验，保持已确认开班不因普通退课撤销。
5. **特殊考试考试前名单冻结时点**：需要实现管理员确认与系统自动更新之间的一致性；冻结后新增资格、不足人数、实际缺考等复杂例外不应擅自扩展为第二批次。
6. **学籍/专业/年级变更时间点**：若选课报名已成功但结算前学生资格变化，结算过程应再次验证合法性；具体事件处理方式由设计评审确定。
7. **准确数值/时间算法**：GPA DECIMAL 精度、时区与截止日界限、异步审核任务的重试机制、随机结算的可追溯实现均应在设计阶段统一并测试。

以上内容是**待设计或尚未确认的边界**，不得在正式需求中写成已获用户批准的额外业务。它们不要求继续扩充第一版模块，但实现前须有明确且可测试的处理原则。
